# <img src="docs/assets/phoenix-key-rounded.png" width="128" align="right" alt=""> UChicago 登录助手<br clear="right">

[English](README.md)

「UChicago 登录助手」是一款供个人使用的 Chrome 插件，帮助你更方便更快捷地登录你的芝加哥大学账号。

确认登录后，插件会填写已保存的账号密码，自动完成支持的 Okta 登录步骤和 Duo 通行密钥验证。

- 支持 my.UChicago、Canvas，以及使用 UChicago 账号登录的第三方应用。
- 自动跟随登录过程中的跳转，不用逐一设置 Duo 子站点的网址。
- 账号信息和新注册的通行密钥保存在当前 Chrome 配置文件中。
- 可切换英文或简体中文，明暗外观跟随系统。

## 安装

需要桌面版 Google Chrome 120 或以上。无需部署服务器、编译源码或安装依赖。

1. 下载或克隆本仓库，也可以解压项目 ZIP，将文件放在固定目录中。
2. 打开 `chrome://extensions`，启用**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择项目内的 **extension** 文件夹。
4. 从 Chrome 的扩展程序菜单打开 **UChicago Login Assistant**，进入**设置**。

更新时，在原目录替换项目文件，到 `chrome://extensions` 重新加载插件，再刷新已打开的登录页面。无需卸载；卸载会删除插件保存的账号密码和通行密钥。

## 开始使用

在**设置 → 账号**中填写 **CNetID 或 UCMEDID** 和**密码**，点击**保存**。需要在插件中自行输入账号密码，Chrome 密码管理器中保存的密码不会自动导入。

点击控制窗口的电源图标，确保插件已启用，然后打开要使用的服务：

| 从哪里开始 | 确认后插件会做什么 |
| --- | --- |
| [my.UChicago 门户](https://portal.uchicago.edu/ais/) | 打开 **Students**（学生）栏目中的 **my.UChicago** 登录链接 |
| [Courses 首页](https://courses.uchicago.edu/) | 进入 Canvas 登录地址 `https://canvas.uchicago.edu/login/1` |
| UChicago Okta 登录页，包括 `https://uchicago.okta.com/app/*` | 自动填写账号密码，完成可识别的登录步骤 |

插件会询问：

> 使用已保存的账号登录 UChicago？

点击**确认**继续；点击**取消**则不执行登录操作。焦点位于页面或确认按钮时，可按 **Enter** 或**空格键**确认，按 **Esc** 取消。在输入框等控件中操作时，按键功能不变。

请从要使用的应用进入登录页，不要直接打开 `uchicago.okta.com` 账号管理首页。插件会跟随同一标签页中的登录跳转，发起登录的网站和登录后的网站都不必以 `uchicago.edu` 结尾。已有有效登录状态时，也可能跳过 Duo，直接进入应用。

### 控制窗口与设置

| 控件 | 用途 |
| --- | --- |
| 电源图标 | 启用或停用插件 |
| 圆形箭头 | 取消或中断后，在当前受支持页面重新询问是否登录 |
| 设置图标 | 管理账号、通行密钥、PIN、语言和本地数据 |

卡片图标表示账号密码已保存，钥匙图标表示本地已有通行密钥。看到钥匙图标，并不代表已经在 Duo 注册成功。

在**设置**顶部选择语言，切换后立即生效，所有插件窗口都会使用所选语言。重新打开或刷新页面时，会保留所选语言。明暗外观由系统设置决定。

**账号**和 **Duo 与通行密钥**分别保存。点击某一栏的**保存**，不会保存另一栏尚未提交的修改。

## Duo 通行密钥

插件自带通行密钥功能，可以在本地生成新密钥，供 Duo 注册公钥。浏览器、系统或实体安全密钥中原有的通行密钥不能直接导入。

### 注册并选择通行密钥

1. 发起一次学校账号登录，在插件提示中确认。登录尚未超时时，用已有方式完成 Duo 验证，在同一标签页进入设备管理。
2. 在 Duo 中添加通行密钥或安全密钥。请求受支持时，插件会询问**保存新的 Duo 通行密钥？** 点击**确认**。
3. 等待 **Duo 提示注册成功**。只在插件中看到新密钥，不代表已经注册完成。
4. 回到**设置 → Duo 与通行密钥**，在**登录时使用的通行密钥**中选中这枚密钥，点击**保存**。
5. 重新从服务入口登录一次，确认进入的是预期账号。

不用填写 Duo 网址，但需要在 Chrome 中允许插件访问 Duo。单独打开 Duo 页面，或未通过插件确认登录时，通行密钥仍由 Chrome 处理。

遇到不兼容的请求，可以点击**改用其他通行密钥**，或继续使用原有 Duo 验证方式。插件不支持硬件证明、仅限系统内置认证器的请求，以及部分 WebAuthn 功能。通行密钥能否使用，仍取决于 Duo 的要求。

### 确认与验证 PIN

点击**确认**后，插件只会在当前标签页继续操作，最多持续五分钟。若 30 秒内收到与所选通行密钥匹配的请求，且满足身份验证要求，可以免于再次确认，完成一次验证。超过这段时间或再次收到请求时，可能需要重新确认。手动跳转到其他页面或登录超时后，需要重新开始。

Duo 要求验证身份时，可以输入在插件中设置的**验证 PIN**，也可以改用其他通行密钥。PIN 可按需设置，长度为 6–128 个字符，与学校密码和设备 PIN 无关，不能用来锁定插件保存的数据。连续输错五次后，需等待五分钟才能再试。

请保留其他 Duo 验证方式。

## 隐私与安全

账号密码、通行密钥私钥和用于校验 PIN 的数据，使用 AES-GCM 加密保存在插件本地的 IndexedDB 中。解密密钥也保存在本地，插件无需额外密码就能读取这些信息。如果他人能控制你的设备、Chrome 配置文件或插件，也可能取得已保存的凭据。

- 插件没有广告、使用情况统计、云同步或 Cookie 采集，不读取 Chrome 密码管理器，也不设接收用户数据的服务器。
- 确认登录后，只会在可识别的 UChicago Okta 登录页填写账号密码。通行密钥仅用于这次登录中经过校验的 Duo 页面，私钥不离开本地。
- 经过其他网站或返回应用时，插件不会在这些页面填写凭据或执行操作。相关网站及其他通行密钥服务适用各自的隐私政策。
- 活动记录只保留最近 24 小时内的最多 20 条，不记录密码、私钥或完整登录网址。插件会定期清理过期记录，启动、读取或新增记录时也会清理。

### 权限说明

| 权限或网站访问范围 | 用途 |
| --- | --- |
| `storage` | 保存设置、最近活动和临时登录状态 |
| `scripting` | 在获准访问的页面加载 Duo 适配器 |
| `webNavigation` | 跟踪登录跳转，确认请求来自当前标签页和页面 |
| `alarms` | 清理过期请求、授权和活动记录 |
| `https://uchicago.okta.com/*` | 识别并完成支持的学校账号登录步骤 |
| `https://*.duosecurity.com/*` | 确认登录后，处理支持的通行密钥请求 |
| `https://portal.uchicago.edu/*` | 从门户进入学生登录 |
| `https://courses.uchicago.edu/*` | 从 Courses 首页进入 Canvas 登录 |

可在 Chrome 的**网站访问权限**中管理上述权限。允许访问 Duo，并不代表插件会自动处理所有 Duo 登录；仍需先确认当前这次登录。

### 删除数据

**设置 → 本地数据 → 清除本地数据**会删除保存的账号密码、通行密钥和 PIN，并重置设置、语言及活动记录。卸载插件或删除对应的 Chrome 配置文件，也会删除这些本地数据。

这些操作不会删除学校账号、移除 Duo 中的注册记录，或删除其他服务保存的通行密钥。如需移除旧的注册记录，请另行前往 Duo 操作，并确保还有其他方式可以登录。

## 常见问题

| 问题 | 怎么处理 |
| --- | --- |
| 没有出现登录提示 | 先保存账号、启用插件，并允许访问相关网站，再刷新入口或真正的 Okta 登录页。账号设置和密码找回页面不会出现提示。 |
| 取消后不再询问 | 点击控制窗口的圆形箭头，**重新发起登录**。 |
| 停在入口页或 Duo 页面 | 检查 Chrome 的网站访问权限，在同一标签页重新登录并确认提示。如果当前步骤无法自动完成，请手动继续。 |
| 出现 Chrome 的通行密钥窗口 | 可能没有匹配的本地密钥、未确认本次登录，或网站需要插件尚不支持的功能。 |
| 又要求确认或输入 PIN | 按提示操作，或改用其他通行密钥。确认有时效，Duo 也可能要求再次验证身份。 |

## 开发

需要 Node.js 22 或以上，没有第三方运行时或测试依赖。

```sh
npm run check                  # 静态检查与文档检查
npm test                       # 界面、本地化和主题的精简测试
npm test -- controller policy  # 运行指定测试组
npm run package                # 静态检查与打包
```

完整测试使用 `npm run test:all`。打包会在 `dist/` 中生成源码目录、ZIP 和 SHA-256 校验文件，不重复执行测试。

可加载的插件位于 `extension/`，使用模拟数据的测试位于 `test/`，检查与打包脚本位于 `scripts/`。
