# <img src="docs/assets/phoenix-key-rounded.png" width="128" align="right" alt=""> UChicago 登录助手<br clear="right">

[English](README.md)

「UChicago 登录助手」是一款供个人使用的 Chrome 插件，帮助您更加轻松快捷地登录您的芝加哥大学账号。

登录学校账号本应是一件简单快捷的事。然而，在芝加哥大学，整个登录过程通常需要经过 Okta 和 Duo 的多个步骤。用户通常需要分别在不同页面输入用户名和密码，等待多次页面跳转，选择验证方式，并通过指纹识别或一次性验证码完成 Duo 验证。由于访问 my.UChicago 和 Canvas 等日常数字平台时经常需要重复这一流程，减少这些重复操作可以让用户在日常使用中更加高效并减轻操作负担。

本插件将在用户每次明确授权后，自动处理芝加哥大学账号登录流程中的重复步骤。在用户保留对身份验证控制的同时，让登录过程更加方便快捷。

- 支持 my.UChicago、Canvas，以及使用芝加哥大学账号登录的第三方应用。
- 在您每次授权登录后，自动完成学校账号登录流程（需提前完成账号和通行密钥设置）。
- 使用符合行业标准的加密方式，将账号信息和通行密钥安全地存储在您的设备上。
- 提供英文和简体中文界面，并支持根据系统自动切换浅色和深色模式。
- 完全开源，完整的源代码和技术实现均在 GitHub 上公开。

当前版本：1.8.3

发布日期：2026 年 10 月 1 日

## 安装

需要桌面版 Google Chrome 122 或以上。无需部署服务器、编译源码或安装依赖。

1. 下载或克隆本仓库，也可以解压项目 ZIP，将文件放在固定目录中。
2. 打开 `chrome://extensions`，启用**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择项目内的 **extension** 文件夹。
4. 首次安装后会自动打开**设置**。以后可从 Chrome 的扩展程序菜单打开 **UChicago Login Assistant**，进入**设置**。

更新时，在原目录替换项目文件，到 `chrome://extensions` 重新加载插件，再刷新已打开的登录页面。无需卸载；卸载会删除插件保存的账号密码和通行密钥。

## 初次设置

### 保存账号并设置登录授权验证

在**设置 → 账号**中填写 **CNetID 或 UCMEDID** 和**密码**，点击**保存**。账号密码需要在插件中输入，Chrome 密码管理器不会自动导入。请确认控制窗口的电源图标处于启用状态。

在**设置 → 登录授权验证**中，您可以使用**设备验证**，或设置**验证口令**。

如果您选择使用**设备验证（推荐）**，Chrome 会调用系统验证窗口，例如 Touch ID 或 Windows Hello；具体方式由设备决定。启用后会显示绿色对勾。关闭设备验证时，需要输入并确认新口令，再完成 Chrome 的设备验证。只有设备支持通过验证凭据派生加密密钥时，才能启用设备验证。

设置或更换**验证口令**时，先输入 6–128 个字符并点击**保存**，再输入一次相同的口令并点击**确认**。两次输入一致后，口令才会保存；设置成功后会显示绿色对勾。

### 添加 Duo 通行密钥

保存尚无可用通行密钥的账号后，插件会询问是否添加通行密钥以启用一键登录。您可以在提示中确认，也可以到**设置 → Duo 与通行密钥**点击**添加通行密钥**。插件会为此打开新的学生登录页面。

1. 插件打开 Duo 的验证方式菜单，选择 **Manage devices**。如果 Duo 要求先验证身份，请使用已有方式完成验证，随后插件会继续。
2. 进入设备管理后，插件会依次选择 **Add a device → Security key → Continue**。在插件的**添加通行密钥**窗口中，点击**继续**。
3. Duo 的设备列表出现新安全密钥后，插件会选择 **Back to login**，再选择 **Security Key**。Duo 完成注册后，这枚密钥即可用于自动验证。

插件会在本地生成新的通行密钥，并将公钥注册到 Duo；无法直接导入 Chrome、操作系统或实体安全密钥中已有的通行密钥。仅在插件中看到新密钥，不代表 Duo 已完成注册。请保留其他 Duo 验证方式。

无需填写 Duo 网址，但请在 Chrome 中允许插件访问 Duo 页面。未通过插件确认的登录，仍由 Chrome 处理 Duo 的通行密钥请求。

## 日常登录

打开您要使用的服务，按插件提示确认登录。以下入口均受支持：

| 从哪里开始 | 确认后插件会做什么 |
| --- | --- |
| [my.UChicago](https://my.uchicago.edu/) | 跳过门户页，直接进入学生登录；支持 HTTP 和 HTTPS |
| [my.UChicago 门户](https://portal.uchicago.edu/ais/) | 不等待门户页加载，直接进入学生登录 |
| [Courses 首页](https://courses.uchicago.edu/) | 进入 Canvas 登录地址 `https://canvas.uchicago.edu/login/1` |
| UChicago Okta 登录页，包括 `https://uchicago.okta.com/app/*` | 自动填写账号密码，完成可识别的登录步骤 |

插件会询问：

> 使用已保存的账号登录 UChicago？

点击**确认**继续，点击**取消**则停止。从 my.UChicago 开始时，提示会在当前标签页打开；取消后进入普通门户页。焦点位于页面或确认按钮时，可按 **Enter** 或**空格键**确认，按 **Esc** 取消。输入框等控件中的按键功能不变。

确认后，请完成已设置的登录授权验证。这次授权只适用于当前标签页中的登录，最长五分钟，期间的正常跳转无需重新授权。如果当前账号有可用的通行密钥，插件会在 Duo 中选择 **Security Key** 并使用该密钥，无需再次确认通行密钥。Duo 可能记住此浏览器并跳过验证；何时需要验证，由 Duo 决定。若 Duo 另行要求验证身份，请按提示自行完成。

您可以切换到其他标签页，插件仍会在已授权的标签页继续处理支持的登录步骤。Duo 验证完成后，如出现 **Is this your device?**，插件会选择 **Yes, this is my device**。已有登录状态时，也可能直接进入应用，无需经过 Duo。

请从您要使用的应用开始，不要直接打开 `uchicago.okta.com` 的账号管理首页。发起登录的应用和登录后的目标网站都不必以 `uchicago.edu` 结尾。下次登录仍需重新确认。

### 控制窗口与已保存的通行密钥

| 控件 | 用途 |
| --- | --- |
| 电源图标 | 启用或停用插件 |
| 圆形箭头 | 取消或中断后，在当前受支持页面重新询问是否登录 |
| 设置图标 | 管理账号、通行密钥、登录授权验证、语言和本地数据 |

控制窗口的卡片图标表示账号密码已保存；钥匙图标表示本地已有通行密钥，不代表 Duo 已接受注册。在**设置**顶部切换语言后，插件窗口会立即更新，刷新页面也会保留选择。明暗外观由系统设置决定。

**Duo 与通行密钥**会显示当前验证方式：已保存的账号有可用密钥时为**自动验证**，否则为**手动验证**。有可用密钥时，“添加通行密钥”入口会隐藏；没有时，请自行完成 Duo 验证。已保存的密钥会显示所属账号、添加时间和删除按钮。

Duo 明确拒绝的密钥会标为**已失效**，不再自动使用。插件会询问是否添加替代密钥；若取消，本次登录交由您手动完成。下次登录会进入设备管理，并在 Duo 准备创建新密钥时再次询问。超时、取消或未匹配到密钥，都不会直接判为失效。已失效或被替代的本地密钥会一直保留，直到您手动删除或清除本地数据。

遇到不兼容的通行密钥请求，可以在出现提示时选择**改用其他通行密钥**，或使用其他 Duo 验证方式。插件不支持硬件证明、仅限系统内置认证器的请求，以及部分 WebAuthn 功能。Duo 会根据自身策略决定是否接受通行密钥。

验证口令与学校密码、设备 PIN 分开设置。连续输错 5 次后，需等待 5 分钟才能再试；连续输错 15 次后，插件会清除保存的本地数据。正确输入一次，错误次数就会清零。取消设备验证不会计入口令错误次数。

## 隐私与安全

插件使用浏览器内置的 Web Crypto API 和 AES-256-GCM，将已保存的用户名、密码及通行密钥私钥加密存放在当前 Chrome 配置文件中。加密密钥随机生成；验证口令通过 PBKDF2-SHA-256 保护这把密钥。启用设备验证时，兼容的设备则通过 WebAuthn PRF 提供保护。验证口令不会以明文保存。设备验证，或较长且不重复使用的验证口令，能提供本插件最强的本地保护。如果两种授权验证方式都未启用，数据仍会加密保存，但登录前不再需要完成额外的授权验证。

- 每次登录都需要您先确认。授权只适用于当前标签页和账号，最长五分钟。使用已保存的信息前，插件会核对当前页面、HTTPS 来源及本次登录流程。
- 密码只会填写在可识别的 UChicago Okta 登录页。通行密钥在本地生成：Duo 注册公钥，私钥留在您的设备上，只用于这次已授权的 Duo 登录中符合要求的请求。插件不会把账号信息填写到中间页面或登录后的目标网站。
- 本项目没有用于接收用户数据的服务器。插件不含广告、使用情况统计或云同步功能，也不会读取 Chrome 密码管理器。确认添加通行密钥后，插件会清理指定学校登录网站的 Cookie，以便重新登录；不会保存 Cookie 内容。
- 最近活动只保留过去 24 小时内的最多 20 条，不记录密码、私钥或完整登录网址。过期记录会自动删除。

### 权限说明

| 权限或网站访问范围 | 用途 |
| --- | --- |
| `storage` | 保存设置、最近活动和临时登录状态 |
| `scripting` | 管理 Duo 页面适配 |
| `webNavigation` | 跟踪登录跳转，确认请求来自当前标签页和页面 |
| `alarms` | 清理过期请求、授权和活动记录 |
| `declarativeNetRequestWithHostAccess` | 在 my.UChicago 跳转到门户之前显示登录确认页 |
| `cookies` | 添加通行密钥前，准备新的学校账号登录 |
| `*://uchicago.okta.com/*` | 识别并完成支持的学校账号登录步骤 |
| `*://*.duosecurity.com/*` | 确认登录后，处理支持的通行密钥请求 |
| `https://portal.uchicago.edu/*` | 从门户进入学生登录 |
| `https://courses.uchicago.edu/*` | 从 Courses 首页进入 Canvas 登录 |
| `*://*.ais.uchicago.edu/*` | 将 AIS 纳入学生登录的网站访问范围，保留网站原有的服务器跳转 |
| `*://my.uchicago.edu/` | 从 HTTP 或 HTTPS 的 my.UChicago 首页直接进入学生登录，不在 HTTP 页面填写账号密码 |

可在 Chrome 的**网站访问权限**中管理上述权限。允许访问 Duo，并不代表插件会自动处理所有 Duo 登录；仍需先确认当前这次登录。

### 删除数据

**设置 → 本地数据 → 清除本地数据**会删除保存的账号密码、通行密钥和验证口令，并重置设置、语言及活动记录。验证口令连续输错 15 次，也会执行相同的本地清除。卸载插件或删除对应的 Chrome 配置文件，同样会删除这些数据。

这些操作不会删除学校账号、移除 Duo 中的注册记录，或删除其他服务保存的通行密钥。如需移除旧的注册记录，请另行前往 Duo 操作，并确保还有其他方式可以登录。

## 常见问题

| 问题 | 怎么处理 |
| --- | --- |
| 没有出现登录提示 | 先保存账号、启用插件，并允许访问相关网站，再刷新入口或真正的 Okta 登录页。账号设置和密码找回页面不会出现提示。 |
| 取消后不再询问 | 点击控制窗口的圆形箭头，重新发起登录。 |
| 停在入口页或 Duo 页面 | 检查 Chrome 的网站访问权限，在同一标签页重新登录并确认提示。如果当前步骤无法自动完成，请手动继续。 |
| 出现 Chrome 的通行密钥窗口 | 没有可用的本地密钥、未确认本次登录或选择其他通行密钥时，这是正常行为。如果已有可用密钥，请重新加载插件，再开始一次新的学校账号登录。未匹配或不支持的请求会先由插件提示，再由您决定是否改用其他通行密钥。 |
| 又要求确认或输入验证口令 | 请完成登录授权验证，或改用其他通行密钥。授权有时效，Duo 也可能再次要求确认身份。 |

## 开发

需要 Node.js 22 或以上，没有第三方运行时或测试依赖。

```sh
npm run check                  # 静态检查与文档检查
npm test                       # 界面、本地化和主题的精简测试
npm test -- controller policy  # 运行指定测试组
npm run package                # 静态检查与打包
```

完整测试使用 `npm run test:all`。打包会在 `dist/` 中生成源码目录、ZIP 和 SHA-256 校验文件，不重复执行测试。

可加载的插件位于 `extension/`，使用模拟数据的测试位于 `test/`，检查与打包脚本位于 `scripts/`。`extension/` 根目录保留插件清单；`background/` 存放后台脚本，`pages/` 存放插件页面，`ui/` 存放共用界面文件，`content/` 存放网页适配代码，`core/` 存放登录逻辑，图标和语言文件分别存放在 `icons/` 与 `locales/`。
